## 4. Semantic Regions and UI

Phase 4 was originally scoped as four tasks; a P0 review before implementation found the `solverStrategy` default disagreed across the codebase, `autoClusterTrip` ran unconditionally outside the undo system, and `4.4`'s intended objective-based region protection was unworkable (see `design.md` Decision 2.5). The tasks below are the corrected scope. 4.2/4.3 are unchanged from the original plan.

- [x] 4.1 Fix the three-way `solverStrategy` default disagreement: `packages/domain/src/schema.ts`'s zod schema currently defaults to `"clusterFirst"` while `apps/web/src/store.ts` (`defaultFlags`) and `apps/web/src/tripFactory.ts` (`defaultSettings`) both default to `"routeFirst"`, and the README/specification.md document route-first as the default. Since `LocalRepository` runs `parseTrip` on every read and write, the zod default silently applied `clusterFirst` to any stored trip missing the field, disagreeing with what the UI reported. Change the zod default to `"routeFirst"` so all sources agree, and confirm nothing else (tests, migrations, fixtures) relied on the old `clusterFirst` zod default.
- [x] 4.2 Move the Capacity-Constrained K-Means logic to the frontend (`apps/web/src/clustering.ts`'s `autoClusterTrip`) to auto-populate empty `Place.region` fields when creating/updating a trip. (Already implemented prior to this review; kept as-is except for the consolidation in 4.6 and the call-site fix in 4.7.)
- [x] 4.3 Expose the `region` field in the UI (e.g., inside the Place editor or place card) so the user can manually control which places belong together. Implemented in `apps/web/src/components/PlaceEditor.tsx`: the free-text box is replaced with a picker over every region string already used elsewhere in the trip (matching an existing string exactly is what makes places group in the solver), plus a "+ New region..." mode to type one, and a "(none - auto-assign)" option to clear it back to empty so auto-clustering reclaims it. Since `Place` carries no persisted provenance flag for "auto-derived vs. user-set", the auto/custom badge is a best-effort heuristic (`isAutoRegionName`, exported and unit-tested in `PlaceEditor.test.ts`) keyed to `applyAutoCluster`'s "District N" naming convention — cosmetic only, and it degrades safely since any edit to the text reads as custom immediately. The control stays visible (not hidden/disabled) under `routeFirst`, since region set in advance is exactly what `clusterFirst` reads the moment a user switches strategy in the DevPanel; an inline hint explains it has no effect until `clusterFirst` is enabled.
- [x] 4.4 Replace the unconditional, `BIG_PENALTY`-weighted `regionMixing` objective term in `packages/solver/src/alns.ts`'s `evaluate()` (currently applied to every solve regardless of strategy, at 1e9/mismatched place — six orders of magnitude above `mustDropped`'s 1000/place, so ALNS would drop hundreds of must-see places before accepting one region-mixed day) with an operator-level constraint, matching `design.md` Decision 2.5:
  - Add an opt-in region-compatibility check to `insertPlace`: a day already hosting a single established region refuses a place carrying a *different* region; an unregioned place is always compatible; a day with no established region accepts anything; a day already mixed by construction is not penalized further but is not made worse either.
  - Apply it only when `problem.settings.solverStrategy === "clusterFirst"`, and only from the ALNS search operators (`recreate`, `relocateDay`, `swapDays`).
  - Do **not** apply it in `repairPass` (`solve.ts`) or the `forceInsert` edit path — both must keep bypassing it so a must-priority place is never left unscheduled, and force-insert never fails, purely over region coherence (existing `itinerary-solver` spec guarantees). Refined during implementation: `repairPass` processes every leftover pooled place regardless of priority, but only `priority === 1` (must) carries that "never silently drop" guarantee, so `repairPass`'s bypass is conditioned on `priority === 1` — a want/nice-priority leftover still respects region compatibility there and stays pooled rather than being dumped onto an unrelated district. `forceInsert` bypasses unconditionally (always an explicit, place-and-day-specific user action). See `design.md` Decision 2.5 and `specs/itinerary-solver/spec.md`'s "Region protection still applies to lower-priority repair" scenario, both updated to match.
  - Remove the `regionMixing` objective term entirely rather than reweighting it — the operator constraint alone satisfies the goal.
  - `dayImbalance`'s existing `clusterFirst` gate (already correct) is unaffected.
- [x] 4.5 Fix `autoClusterTrip`'s call site in `apps/web/src/store.ts`'s `requestSolve` (currently unconditional and applied via a bare `set()` + `persist()` outside the undo system, so it silently relabels places' `region` and persists on every solve — including `routeFirst` trips and every drag — with no undo entry and no dirty flag): gate the call on `trip.settings.solverStrategy === "clusterFirst"`, and route the mutation through the store's existing `mutateTrip` undoable path instead. Refactor `apps/web/src/clustering.ts` so the mutation is available both as the existing `autoClusterTrip(trip): Trip` (unchanged external behavior, still used wherever else it's called) and as a draft-mutating recipe `mutateTrip` can run directly, so the auto-assignment becomes a normal undoable step (and a no-op when nothing changed, via immer's identity check) instead of an invisible side effect.
- [x] 4.6 Consolidate the duplicated k-means implementations: `packages/solver/src/kmeans.ts` (currently imported by nothing) and `apps/web/src/clustering.ts`'s hand-rolled copy (near-identical k-means++ seeding + 10-iteration Lloyd loop, plus a capacity constraint bolted on only in the app copy) are the same algorithm, already diverged. Make `packages/solver/src/kmeans.ts` the single implementation with the capacity constraint as an optional parameter, export it from `packages/solver/src/index.ts`, and have `apps/web/src/clustering.ts` call it instead of reimplementing. Add `packages/solver/src/kmeans.test.ts` and `apps/web/src/clustering.test.ts` (currently zero coverage despite running on every solve).
